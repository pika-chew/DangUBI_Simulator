# 구현 착수 계획

## 확정 사항

React/TypeScript 관리 화면, Python FastAPI 제어 API, Go/Paho Worker, MQTT 연결 풀, AWS 최종 환경 추후 선택. 개발 기반 구성은 즉시 진행한다.

2026-11-16 추가 확정: 공통 연결 엔진과 연결 풀/차량별 전체 연결 비교를 1차 구현에 포함한다. 실행 전에 연결 수·배정·유지 정책을 지정하고 실행 중 고정한다. 실행 중 증감·재배정은 후속 범위다.

## 남은 확인 항목과 시점

| 항목 | 현재 처리 | 확인 시점 |
|---|---|---|
| OBD 표/예제 충돌 | 표 기준 3/4와 필수 필드를 개발 기준으로 사용. 호환성 확정 아님 | 실제 수신 대상과 전송 연동 전 |
| 토픽·차량 식별 | 설정으로 분리. 개발 예시 sim/{run_id}/{vehicle_id}/obd | 실제 IoT 전송 전 |
| AWS 접속 | 리전·데이터 endpoint·인증서·정책은 외부 설정. 개인 키는 채팅에 요청하지 않음 | 실제 IoT 연결 시험 전 |
| QoS 등 | QoS 1, retain=false, 묶음 없음은 잠정 개발 기본값 | 첫 전송 기능 검토 시 |
| 차량 현실성 | 내연기관·기본 경로·상태 기반 근사 모델은 잠정 개발 기준 | 자동 생성 기능 구현 전 상세 검토 |
| 목표 규모·시간·비용 | 조정 가능한 설정으로 구현, 무제한 AWS 실행 기본값 없음 | AWS 부하 시험과 자원 산정 전 |

## 순서 및 완료 기준

1. 개발 기반: 저장소·폴더·VS Code 구성, 필수 개발 도구 확인. 현재 진행 단계.
2. 수동 전송 기능: 입력→미리보기→API→Worker 흐름과 1/N건 전송. AWS 설정 전에는 실제 송신 없는 확인 기능으로 검토하고 이를 전송 성공으로 표시하지 않는다.
3. 공통 연결 엔진 및 AWS 연결 확인: 풀/차량별 일대일 배정, 실행 전 설정 검증, 설정 변경 차단, Client ID 고유성, 접속 속도 제한·장애 재연결을 구현한다. 모의 전송으로 배정·수량·유지 정책부터 확인한 뒤 수신 규격·토픽·접속 설정 후 제한된 실제 전송과 PUBACK를 확인한다. 같은 데이터와 조건의 별도 실행으로 두 방식을 비교한다.
4. 상태 기반 생성: 차량 전이, seed 재현, 거리·Trip 누적 계산.
5. 트래픽 제어: 차량/TPS 모드, 연결 풀 속도 제한, 스케줄·중단·재개.
6. AWS 실행 환경 결정 및 분산 실행: 단일 Worker 측정 후 비용·성능 비교, 장시간 테스트.
