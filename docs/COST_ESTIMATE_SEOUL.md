# 서울 리전 1만 대·3일 전송 비용 추정

산정일: 2026-11-16. 설계 검토용 추정이며 배포 승인이나 자원 성능 보장이 아니다. AWS 최종 실행 환경은 추후 선택한다.

## 계산 조건

- 차량 10,000대, 기간 3일=72시간. 기본 해석은 차량당 하루 2시간, 3일 합계 6시간 운행.
- 차량별 총 운행시간 합계 60,000 차량·시간. Microtrip은 운행 중 2초마다, 시동 OFF에는 생성하지 않음.
- 하루 차량별 운행 1회 및 종료 Trip 1건 추가. 실제 운행 횟수가 늘면 Trip도 증가.
- 메시지당 1,024바이트 가정. UTF-8 JSON 전체가 5KB 이하인 정상 Publish 1건을 과금 1단위로 산정. 묶음 없음.
- MQTT QoS 1, retain=false. 별도 구독자에게 전달되는 application Publish, Rule, Shadow, Registry 반복 작업은 기본 시나리오에서 사용하지 않음.
- 해당 계정의 월 메시지 사용량이 첫 10억 구간에 있다고 가정. 무료 사용량·크레딧·약정·세금·환율 제외.

## 연결 풀 산정

100연결을 72시간 유지한다. 연결당 운용 상한은 70 Publish/s로 잡아 총 7,000/s까지의 예약 용량을 확보하는 예시다. 피크 Microtrip은 연결당 평균 50/s로 분산된다. AWS 연결당 공식 상한 100/s 및 계정 수신 한도는 별도 확인한다. 모든 미확인 요청·바이트 제한을 충족하는지는 실측해야 한다.

- 연결·분 = 100×72×60 = 432,000.
- 연결 유지비 = 432,000÷1,000,000×0.096 = **$0.041472**.
- 메시지비 = 108,030,000÷1,000,000×1.20 = **$129.636**.
- **기본 IoT 수신·연결 합계 = $129.677472, 약 $129.68.**

100개의 MQTT 연결은 100개의 서버·공용 IP를 의미하지 않는다. 아래 예시에서는 Worker 2개가 각 50연결을 보유한다.

|---|---:|---:|---:|
| 풀 100개, 72시간 | 432,000 | $0.041472 | $129.677472 |

본 조건에서 운행 시 연결 대비 풀의 IoT 요금 차이는 약 $0.30뿐이다. 풀은 연결비 자체보다 송신 측 자원·접속 관리 부담을 줄이는 의미가 크다.

## 추가 기능에 따른 변동

- 모든 메시지를 MQTT 구독자 1개에 재전달: 같은 과금 크기 가정 시 **+$129.636**의 메시지비. PUBACK를 구독자에게 전달되는 데이터 메시지 1건으로 계산하지 않는다.
- 매 메시지에 Rule 1회·Action 1회: **+$38.8908**. Lambda·Firehose·S3 비용은 별도이며 본 프로젝트 기본 범위에서 제외.
- 모든 메시지가 5KB 초과 10KB 이하라면 메시지 과금은 2단위로 증가하여 메시지비 **$259.272**. 연결비는 그대로.
- Basic Ingest 경로는 broker 경로와 목적이 달라 기본 계산에 적용하지 않았다.
- 실제 데이터 저장이 필요하면 IoT Core 수신 자체와 영구 저장을 구분해야 한다. 약 110.62GB 원본을 어디에 어떤 주기로 저장하는지에 따라 별도 견적 필요.

산식 결과는 cost-estimate-calculation.json과 대조했다. 실제 AWS 자원 생성·전송·청구 확인은 하지 않았다.

## 설정 변경과 배포비의 관계

차량 중심 모드에서 같은 운행시간·주기로 차량을 1,000→10,000대로 늘리면 생성·전송량이 10배다. 메시지 요금은 같은 가격 구간에서는 10배이며 차량 상태 계산·메모리·직렬화 작업도 증가한다. TPS 중심 모드에서 전체 발행량을 고정하면 차량 수만 늘었다고 메시지 요금이 10배가 되는 것은 아니다.

풀과 전체 연결은 같은 차량 데이터를 생성하므로 연결 방식만 바꾸어도 메시지 수가 줄지는 않는다. 전체 연결은 차량별 소켓·TLS·keepalive·재연결·미확인 전송 상태를 유지하므로 송신 Worker 자원 요구가 커질 수 있다. 한 Worker에서 여러 Client를 관리하므로 차량 수가 곧 서버 수는 아니다.

Fargate/EC2 실행비는 배정한 자원과 실행시간을 기준으로 결정된다. 같은 자원을 같은 시간 유지하면 설정 변경으로 실제 CPU 사용률이 올라가더라도 기본 자원 요금이 자동으로 10배가 되지는 않는다. 처리 용량 부족 시 자원을 늘리거나 Worker를 추가할 때 비용이 증가한다. 자원을 그대로 두면 목표 TPS 미달·큐 증가·연결 오류가 발생할 수 있다. 본 계산기는 차량 설정에서 필요 Worker 수를 자동 추정하지 않으며, 실행비 입력은 별도다. 실측한 차량 상태 수·연결 수·TPS·메시지 크기별 자원 프로필을 확보한 뒤 자원 추천을 구현해야 한다.
