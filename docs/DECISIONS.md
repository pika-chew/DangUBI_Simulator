# 결정 및 미확정 사항

## 사용자 요구로 확정된 범위

- OBD 차량 데이터 생성, 트래픽 제어, AWS IoT Core 연결·전송.
- Notion 설계제안서 반영. 데이터/파이프라인 검증 제외.
- 설계 초안 → 사용자 피드백·확정 → 로컬 VS Code 구현 → AWS 배포 → 필수 기능 테스트.
- 한국어 소통, 작업 전 목적·예상 결과 안내, 공식 자료 확인, 공유 작업 기록 유지.
- 사용자 수정사항을 인지했을 때 GitHub에서 버전관리를 지원할 장치 마련.

## 검토 대기

2026-11-16 후속 사용자 확정: 연결 풀 방식 채택. AWS 최종 운영 환경은 추후 선택. 개발 기반 구성 단계로 진행한다. 차량별 독립 연결 기능은 별도 추가 범위이며 연결 풀 채택만으로 구현 우선순위를 확정하지 않는다.

2026-11-16 사용자 확정: React/TypeScript 관리 UI, Python FastAPI 제어 API, Go Worker 및 제시한 MQTT 라이브러리 구성으로 진행한다. AWS 배포 환경과 연결 풀 기본값은 추가 설명·비교 후 검토한다.

| ID | 제안 | 확정에 필요한 것 |
|---|---|---|
| D01 | OBD 3/4와 필수 필드 목록 우선 | 실제 수신 계약·자료형·단위 |
| D02 | 내연기관 상태 기반 생성 + 수동 UI | 현실성 수준·운행 프로필 |
| D03 | 연결 풀 기본: 사용자 확정 | 실제 전송 전 풀 사용이 가능한 토픽·인증 정책 확인 |
| D04 | React / FastAPI / Go / Paho: 사용자 확정 | 구현 시 호환 버전 고정 |
| D05 | 운영 환경은 단일 Worker 측정 후, 분산 배포 자동화 완성 전에 선택하는 안 | AWS_OPTIONS 비교 검토, 리전·예산·실측 |
| D06 | 단계적 부하 증가 및 24시간 시험 | 차량 수·목표 TPS·오차·시간 |
| D07 | 작업 단위 자동 커밋·push | 구현 단계 연결 설정, 변경 감지 범위 |

초안 작성만으로 위 제안을 승인 처리하지 않는다. 변경 시 날짜, 결정, 근거, 영향과 사용자 확정 여부를 추가한다.
