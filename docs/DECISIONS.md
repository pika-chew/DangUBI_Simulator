# 결정 및 미확정 사항

## 사용자 요구로 확정된 범위

- OBD 차량 데이터 생성, 트래픽 제어, AWS IoT Core 연결·전송.
- Notion 설계제안서 반영. 데이터/파이프라인 검증 제외.
- 설계 초안 → 사용자 피드백·확정 → 로컬 VS Code 구현 → AWS 배포 → 필수 기능 테스트.
- 한국어 소통, 작업 전 목적·예상 결과 안내, 공식 자료 확인, 공유 작업 기록 유지.
- 사용자 수정사항을 인지했을 때 GitHub에서 버전관리를 지원할 장치 마련.
- 2026-11-16 사용자 확정: 공통 연결 엔진을 1차 구현 범위에 포함한다. 연결 풀과 차량별 전체 연결을 실행별 설정으로 비교한다. 연결 수·배정 방식·배정표는 실행 전에 정하고 실행 중 고정한다. 실행 중 연결 수 증감·차량 재배정은 후속 기능이다. 연결 장애 복구와 운행에 따른 접속/해제는 고정된 유지 정책 안에서 허용하며, 실제 동시 접속 수와 설정 수를 구분한다.

## 검토 대기

2026-11-16 첫 구현 선택: 로컬 첫 실행본은 실제 송신을 지원하지 않는 dry_run 전용이다. API→Go는 stdin/stdout JSON, 개발 상태는 SQLite(.local)로 구성했다. 운영 AWS 환경을 확정하는 결정이 아니다. 한 실행 최대 10,000건, 배정표 100대·샘플 10건 표시/보관으로 제한한다. 미확정 규격은 개발 JSON Schema에 명시하고 수신 호환성으로 간주하지 않는다.

2026-11-16 비용 비교 UI 수정: 풀 운행 연동은 전체 차량 운행 시간대의 합집합, 차량별 연결은 각 차량 운행시간을 적용하는 기존 의미를 유지한다. 동일 기본 데이터에 상시/운행 연동을 나누어 표시하고 동시 운행 시 양쪽 유지시간이 같아지는 선택지를 제공한다. 기존 JSON은 직접 지정 배치로 호환한다. AWS 실행 구성 결정 변경은 없다.

2026-11-16 사용자 요청에 따라 독립 비용 계산기(HTML + 설정 JSON + HTTP GET 예시)를 작성했다. AWS 운영 환경 결정과 분리된 검토 도구다. 30일 내 동일 청구월, 평균 운행량 근사, 풀 가동시간 직접 입력, 메시지/연결/실행비·기타 예산 분리 원칙을 적용했다. 환율·세율·단가는 변경 가능한 사용자 가정으로 표시한다.

2026-11-16 연결 구조 추가 조사: AWS 최종 환경 추후 선택 재확인. 풀은 별도 broker/중계 서버가 아닌 Worker 내부 직접 발행 기능으로 명확화. 차량별 직접 MQTT·HTTPS·WSS·Greengrass 대안은 MQTT_CONNECTION_REVIEW.md에 기록. 이번 질문만으로 기존 풀 채택을 변경하지 않으며 추가 전송 방식 구현을 승인 처리하지 않는다.

2026-11-16 후속 사용자 확정: 연결 풀 방식 채택. AWS 최종 운영 환경은 추후 선택. 개발 기반 구성 단계로 진행한다. 차량별 독립 연결 기능은 별도 추가 범위이며 연결 풀 채택만으로 구현 우선순위를 확정하지 않는다.

2026-11-16 사용자 확정: React/TypeScript 관리 UI, Python FastAPI 제어 API, Go Worker 및 제시한 MQTT 라이브러리 구성으로 진행한다. AWS 배포 환경과 연결 풀 기본값은 추가 설명·비교 후 검토한다.
