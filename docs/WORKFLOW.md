# 작업 컨텍스트 공유와 버전관리

## 지금 적용한 장치

루트 AGENTS.md가 작업 규칙이고 STATUS가 최신 현황, DESIGN이 검토 중 설계, DECISIONS가 확정/미확정 구분, SOURCES가 근거다. 각 작업은 시작 시 이 문서를 읽고 종료 시 결과를 갱신한다. 한국어 응답, 작업 전 목적·기대 결과 설명도 AGENTS에 기록했다.

다른 채팅·Work·Codex 작업에는 이 프로젝트 폴더 또는 같은 저장소를 연결하고 AGENTS.md와 STATUS.md를 먼저 읽도록 한다. 기존 대화 전체를 복사하는 대신 결정·상태·산출물 링크를 공유한다. 저장되지 않은 대화나 다른 서비스의 상태가 자동 공유되지는 않는다. GitHub 연결 후 같은 커밋을 기준으로 읽어야 한다.

## 구현 단계에서 마련할 자동 버전관리

1. 저장소를 로컬에 연결하고 VS Code에서 이 폴더를 연다. 기존 파일과 사용자 변경사항을 확인한 뒤 초기 문서 커밋을 만든다.
2. 작업 시작 시 원격 상태와 로컬 차이를 확인한다. 강제 push나 사용자 변경 덮어쓰기는 하지 않는다.
3. 사용자 수정은 작업 시작·종료 시 diff로 인지한다. 상시 감지가 필요하면 VS Code 작업 또는 로컬 감시 프로세스를 별도 구현한다.
4. 감지된 변경은 저장 완료·유휴시간을 기다려 중간 편집을 묶고, 비밀정보 제외·관련 기능 확인 후 작업 단위로 자동 커밋한다. 자동 커밋은 기능 완성 판정과 구분한다.
5. 개발 브랜치로 push하고 GitHub Actions에서 필수 테스트를 수행한다. 충돌·인증 실패·검사 실패는 상태에 기록하고 사용자에게 알린다. 실패한 push를 동기화 완료로 보고하지 않는다.
6. 배포는 버전관리와 분리한다. 모든 수정이 곧바로 AWS 배포나 부하 실행을 유발하지 않게 한다.

현재는 위 절차를 문서화한 상태다. 자동 감시·커밋·push 서비스는 가동하지 않았다. 감시가 가동되어도 로컬 PC/프로세스 종료 시 동작하지 않으므로 실행 상태와 마지막 동기화 커밋을 표시하도록 구현한다.

## 작업 종료 기록 형식

- 작업 목적과 산출물
- 실제 변경 내용 및 파일
- 수행한 확인과 결과, 수행하지 않은 테스트
- 결정·가정·남은 항목
- 다음 작업과 선행 조건

문서 충돌 시 사용자의 최신 명시적 지시를 반영하고, 근거와 변경 이력을 남긴다. 동시에 여러 작업이 문서를 수정하면 최신 내용을 다시 읽고 병합한다.
